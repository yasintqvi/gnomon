# Verification Criteria

## Purpose

Define reusable verification criteria used to objectively determine whether an artifact complies with approved project knowledge.

Verification produces evidence.

It does not perform engineering reasoning or introduce new project knowledge.

---

# Specification

- Every applicable requirement is implemented.
- Every acceptance criterion is satisfied.
- No implemented behavior contradicts the specification.

---

# Domain

- Domain terminology is consistent.
- Domain rules are preserved.
- Domain invariants are respected.

---

# Architecture

- Implementation follows the approved architecture.
- Applicable ADRs are respected.
- Architectural constraints are satisfied.

---

# Contracts

- Applicable artifact contracts are satisfied.
- Required sections exist.
- Required outputs are produced.

---

# Stack

- Approved technologies are used.
- Stack constraints are respected.

---

# Conventions

- Naming conventions are respected.
- Directory structure follows project conventions.
- Coding conventions are satisfied.

---

# Documentation

- Required documentation exists.
- Documentation matches implementation.

---

# Testing

- Required tests exist.
- Tests pass successfully.
- Required scenarios are covered.

---

# Static Analysis

- Static analysis passes.
- No type violations exist.

---

# Formatting

- Formatting passes.
- Linting passes.

---

# Verification Result

Every criterion must produce one of the following results:

- PASS
- FAIL
- UNVERIFIABLE

Supporting evidence is mandatory.
